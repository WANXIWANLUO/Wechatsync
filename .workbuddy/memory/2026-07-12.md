# 2026-07-12

## 调查：「调整并同步」调整页改成 Markdown 编辑器 + 按平台转 HTML/MD 发布

### 结论
- 完全可以改。更重要的是：**「按平台不同转 HTML 或 Markdown 发布」这条能力架构上已经存在并接好线了**，只是藏在代码里不易发现。真正要写的核心工作只有「编辑器 UI 从富文本换成 Markdown」+「同步边界处处理格式」。

### 现状（调整页 = `packages/extension/src/editor/EditorApp.tsx`）
- 是 contentEditable 的 WYSIWYG 富文本 HTML 编辑器：标题 `<h1 contentEditable>`，正文 `<div contentEditable dangerouslySetInnerHTML>`。
- 同步时 `getEditedArticle()` 直接取 `titleRef.innerText` + `contentRef.innerHTML`（HTML）发给父窗口。

### 已有的按平台格式转换基建（重点）
- `packages/core/src/adapters/types.ts`：`PreprocessConfig.outputFormat: 'html' | 'markdown'`，默认 `'html'`。
- 各平台适配器声明自己的 `preprocessConfig.outputFormat`：
  - markdown：csdn、cnblogs、cto51、douban、imooc
  - html：zhihu、bilibili、baijiahao、eastmoney 等（其余默认 html）
- 同步链路：`background/index.ts` → 给 content script 发 `PREPROCESS_FOR_PLATFORMS` → `extension/src/lib/content-processor.ts` 的 `preprocessForPlatform(rawHtml, config)` 对**每个平台**生成 `{html, markdown}`（已预处理），存进 `article.platformContents[platformId]`。
- `extension/src/adapters/index.ts` 的 `syncToPlatform` 把对应平台的 `{html, markdown}` 注入 article，各适配器 `publish` 按自己 outputFormat 选用 `article.html` 或 `article.markdown`（已验证：csdn 读 `article.markdown`，知乎读 `article.html`）。
- 转换库齐全：`htmlToMarkdownNative`（turndown，HTML→MD）、`markdownToHtml`（marked，MD→HTML）、`markdownToDraft`（豆瓣）都在 `@wechatsync/core` / `extension/src/lib`。

### 改造要点（若要做）
- 入口：编辑器收 `ARTICLE_DATA`（content 是 HTML）时用 `htmlToMarkdownNative` 转 MD 显示。
- `getEditedArticle()` 需同时产出 `article.markdown = md` 和 `article.html = markdownToHtml(md)`，否则 HTML 平台 break。
- 推荐方案 B（避免 MD 平台往返降质）：HTML 平台用 `markdownToHtml(md)` 当 rawHtml 预处理取 html；Markdown 平台直接透传原始 md，pipeline 需识别「源已是 markdown」。
- 坑：失去 WYSIWYG，必须做预览分栏；图片上传依赖 HTML `<img>`，`markdownToHtml` 会把 `![](url)` 转 `<img>` 故链路保留，但粘贴/上传图片交互要单独做；当前 content-processor 对 HTML 代码块/微信行号的特殊处理对 MD 源未必适用；无现成 MD 编辑器库，引入会增加扩展体积。

### 决策待定（征求用户）
- 是否保留「富文本/Markdown」切换，而非一刀切替换。
- 引哪个编辑器库（CodeMirror6 / @uiw/react-md-editor / EasyMDE）。
- 是否做左编辑右预览分栏。

## 迭代：封面图布局重设计（解决「突兀占用位置」）

用户问封面图怎么设计才不突兀。

### 根因

- 标题在 MD 模式也是 1400px 宽 h1，同样违和。

### 改动（`EditorApp.tsx` 文章头部区）

- 编辑器（MarkdownEditor）保持全宽工作区，与窄头部形成「窄头部 + 宽工作区」的清晰分区。

## 迭代：目录跳转与滚动同步冲突（需点两次）

问题：点目录跳转到某标题，要连点两次才定位。根因 `jumpTo` 同时触发编辑器 `scrollIntoView` 与预览 `scrollIntoView({behavior:'smooth'})`，两侧滚动都冒泡触发同步监听，同步按"比例"反拉对方，两个动画互拉、落点不稳。

### 修复（`MarkdownEditor.tsx`）
- 新增 `jumpingRef` 守卫；滚动同步 `sync` 顶部加 `if (jumpingRef.current) return`。
- `jumpTo` 改为：先置 `jumpingRef.current=true` 屏蔽同步 → 编辑器 `scrollIntoView` 定位 → 预览**直接按标题实际位置** `pv.scrollTop = el.getBoundingClientRect().top - pv.getBoundingClientRect().top + pv.scrollTop - 8` 定位（不再用 smooth `scrollIntoView`，避免再次冒泡互拉）→ `setTimeout(450ms)` 后复位 `jumpingRef`。
- 结果：一次点击两侧同时精确落位，不再互拉。

### 验证
- `pnpm build` 通过，editor 646KB(220KB gzip)；typecheck 零错误。

## BUG 修复：调整页空白 + RangeError「Block decorations may not be specified via plugins」

现象：调整页整页空白，控制台抛 `RangeError: Block decorations may not be specified via plugins`，并级联 `TypeError: Cannot read properties of undefined (reading 'coordsAt'/'update')`。

### 根因（关键 CM6 约束）
- `@codemirror/view` 的 `ViewPlugin` **不允许提供 block 类型 decoration**（即 `Decoration.replace({ block:true })` 的图片块 `ImageBlockWidget`）。
- 一但有独立成行的 `![](url)` 触发该 block 装饰，CM6 在实例化插件时即抛 RangeError，编辑器组件渲染崩溃 → 整页空白；后续的 `coordsAt`/`update` 是崩溃级联，非独立问题。

### 修复
- 把 `markdownLivePreview()` 从 `ViewPlugin.fromClass({decorations})` 改为 **`StateField.define<DecorationSet>`**，用 `provide: (f) => EditorView.decorations.from(f)` 提供装饰——这是 CM6 唯一合法的 block 装饰来源。
- `buildMarkdownDecorations(view)` 改为 `buildMarkdownDecorations(state: EditorState)`：因 StateField 无 `view.visibleRanges`，改为遍历整篇 `syntaxTree(state).iterate({from:0,to:doc.length})`（文章体量小，全量扫描流畅）。`addLineDecoEach` 同步改吃 `state`。
- StateField `update` 不能读 `tr.viewportChanged`（Transaction 无该属性），改为 `tr.docChanged || syntaxTree(tr.startState) !== syntaxTree(tr.state)`——后者捕获**语法树异步解析完成**派发的无 docChanged 事务，否则初始化/编辑后装饰会缺失或滞后。
- 新增直接依赖 `@codemirror/state@6.7.1`（pnpm 严格模式需显式声明才能 import）；`pnpm install --filter @wechatsync/extension` 后已正确软链。

### 验证
- `pnpm typecheck` 零 MarkdownEditor 错误（`douban.ts` 预存报错仍在，无关）；`pnpm build` 通过，体积 651KB(222KB gzip) 不变。
- 经验：**任何 block decoration 必须经 StateField + `EditorView.decorations.from`，绝不可走 ViewPlugin**。这是 CM6 高频坑。

## BUG 修复：源码区点击光标偏下（点第一行落到下面行）

现象：在源码区点击某行，光标落在其下方一行；含图片时尤其明显（偏移量≈图片高度）。

### 根因
- `ImageBlockWidget`（block 装饰，图片完整尺寸块）高度在 CodeMirror 初始 measure 时尚未确定（图片异步加载，初始高度偏小/为 0）。
- 图片加载完成后 DOM 高度变大、把下方文本实际推下去，但 CM 的「屏幕坐标↔文档位置」映射用的是 measure 时缓存的旧高度 → 点击落点整体偏移。
- 这是 CM6 block widget 的经典坑：**widget 高度在 measure 之后变化，必须主动触发重测**。

### 修复（`MarkdownEditor.tsx` 两个图片 Widget 的 `toDOM`）
- `img` 的 `load` 与 `error` 回调里，用 `EditorView.findFromDOM(wrap)` 取到 view，调用 `view.requestMeasure()` 刷新坐标映射。
- 块级 `ImageBlockWidget` 与行内 `ImageInlineWidget` 都加（行内图加载后同样会微移行高）。
- `ignoreEvent()=>true` 保持不变（图片不吞光标，下方文字仍可编辑）。

### 验证
- `pnpm typecheck` 零错误；`pnpm build` 通过，体积不变。
- 经验：CM6 中任何异步改变高度的 widget（图片/远程字体/懒加载内容）必须在尺寸变化后 `requestMeasure`，否则点击/选区映射错位。

## 迭代：源码区图片改为「折叠卡 + 点击展开编辑」+ 修复部分图片不显示

用户反馈：① 源码框里有的图片没显示 ② 图片链接源码应默认收缩成图片描述样式、点击再展开编辑，方便源码/预览两侧高度大致同步。

- **`IMAGE_RE` 是全局正则 `/g`**：`.exec()` 会沿用上次匹配的 `lastIndex`，第 2、3… 张图常从错误偏移开始匹配 → `url` 解析为空 → 图片不显示。→ 去掉 `/g`。

- 新增 `toggleImageEffect = StateEffect.define<number>()` 与 `expandedImagesField = StateField<Set<number>>`（key=行号，空集=默认全部折叠）。

### 三轮修复：行号错位（根因修正）、预览滚动乱跳、目录跳转不对称

三个问题同时修复（`pnpm typecheck` 零错误、`pnpm build` 通过）：

1. **行号错位**：根因是 `.cm-img-block` 的 CSS `margin:6px 0`。margin 在元素盒**外**，CM6 测量 widget DOM 高度时不一定准确计入 → 每张图实际高度比 CM 测到的多 12px → 后续所有行号按"矮了"的旧高度累积排布 → 越往下越偏。修复：把 `margin` 改成 `padding: 6px 0`（盒内，CM 一定测对），同步 `estimatedHeight` 从 440 上调到 460（含 padding）。CSS 注明了"不能用 margin 做间距"的坑。

2. **预览编辑时滚动疯狂乱跳（三轮修复，最终方案）**：
   - 第一轮（rAF 恢复）：时序太慢，浏览器自动滚屏在前、保存/恢复在后 → 两跳 = 乱跳
   - 第二轮（overflow-anchor:none + sync restore）：仍无法阻止 contentEditable 的浏览器级滚屏行为
   - **最终方案**：彻底去掉 contentEditable。预览改为**只读 + 点击定位**（CSDN/VS Code 标准做法）：
     - 预览 div 去掉 `contentEditable`/`onInput`/`onFocus`/`onBlur`/`onScroll`
     - 新增 `handlePreviewClick`：点击标题 → 精确匹配 headings 数组定位；点击正文 → 模糊文本搜索对应源码行
     - 编辑全部走源码，预览通过 `useEffect` (html+view 依赖) 自动从 md→html 同步渲染
     - 去掉 `previewFocusedRef`/`previewScrollRef`/`htmlToMarkdownNative` 等所有 contentEditable 相关代码
     - 文案更新："实时预览（可点选编辑）" → "实时预览（点击定位源码）"

3. **目录跳转不对称**（预览标题在顶部、源码在底部）：CM 侧用的是 `scrollIntoView:true`，它只保证"可见"（常把目标行推到底部），而预览侧用的是精确定位 `scrollTop = target.top - editorTop - 8`（到顶部）。修复：CM 也改成手动 `coordsAtPos` + `scrollDOM.scrollTop` 精确定位到顶部（和预览画齐）。去掉了 `scrollIntoView:true`。

### 验证
- `pnpm typecheck` 零错误；`pnpm build` 通过。
